# 第一周 - 角色与职能清单

## 一、角色总览

小卖部经营场景中涉及以下四类核心角色，各角色的职责和权限边界明确，为后续数据库权限设计提供依据。

| 角色 | 角色说明 | 人数（参考） | 核心职责 |
|---|---|---|---|
| 店长 | 店铺最高管理者，负责全面运营 | 1人 | 商品管理、库存管理、员工管理、销售统计、财务核对 |
| 店员 | 日常运营执行者，负责收银和理货 | 1-2人 | 收银结账、商品上架、库存盘点、会员注册、顾客服务 |
| 会员 | 注册会员顾客，享受积分和优惠 | 不限 | 购物消费、查看积分、享受会员权益 |
| 顾客（非会员） | 普通散客，无注册信息 | 不限 | 购物消费，不享受会员权益 |

---

## 二、各角色详细职能

### 1. 店长

#### 基本信息
- **角色定位**：店铺最高管理者，拥有系统全部权限
- **使用系统方式**：后台管理端（PC端）

#### 核心职责

| 职责类别 | 具体职责 | 操作频率 |
|---|---|---|
| 商品管理 | 新增商品、修改商品信息（名称、分类、单价、进价）、商品上下架 | 按需 |
| 商品管理 | 设置商品最低库存阈值 | 按需 |
| 库存管理 | 查看库存报表、处理库存预警、审批入库/出库 | 每日 |
| 库存管理 | 发起库存盘点、审批盘点差异调整 | 每月 |
| 订单管理 | 查看所有订单记录、销售统计报表、日/月销售额统计 | 每日 |
| 订单管理 | 审批大额退货退款申请 | 按需 |
| 会员管理 | 查看会员列表、会员消费统计、调整会员等级 | 按需 |
| 员工管理 | 新增/删除员工账号、分配员工角色和权限、重置员工密码 | 按需 |
| 员工管理 | 查看员工交接班记录、考核员工绩效 | 每月 |
| 财务管理 | 核对每日收银现金、查看收支报表、利润核算 | 每日/每月 |

#### 可操作数据范围
- **商品表**：全部读写权限
- **库存表**：全部读写权限
- **订单表**：全部读写权限（含删除、退款审批）
- **订单明细表**：全部读权限
- **会员表**：全部读写权限
- **员工表**：全部读写权限（含薪资等敏感信息）

#### 不可操作/受限项
- 无（系统最高权限）

---

### 2. 店员

#### 基本信息
- **角色定位**：日常运营执行者，收银与理货
- **使用系统方式**：收银端（PC端/平板端）

#### 核心职责

| 职责类别 | 具体职责 | 操作频率 |
|---|---|---|
| 收银结账 | 录入顾客购买的商品和数量、生成订单 | 每日高频 |
| 收银结账 | 处理顾客支付（现金/扫码）、确认收款 | 每日高频 |
| 收银结账 | 打印购物小票、交付商品 | 每日高频 |
| 会员服务 | 为顾客注册会员、录入会员信息 | 按需 |
| 会员服务 | 帮助会员查询积分余额、消费记录 | 按需 |
| 商品管理 | 商品到货验收、录入入库信息 | 按需 |
| 商品管理 | 商品上架、整理货架、更新货架位置 | 每日 |
| 库存管理 | 配合店长进行库存盘点、录入实盘数量 | 每月 |
| 库存管理 | 发现库存不足时及时上报店长 | 每日 |
| 顾客服务 | 解答顾客咨询、处理简单退换货 | 每日 |
| 交接班 | 清点收银现金、核对销售记录、填写交接班记录 | 每日两次 |

#### 可操作数据范围

| 数据表 | 权限 | 说明 |
|---|---|---|
| 商品表 | 只读 | 可查看商品名称、单价、分类，不可修改 |
| 库存表 | 读 + 入库操作 | 可查看库存数量，可执行入库操作，不可手动调整库存 |
| 订单表 | 读写（当日） | 可创建当日订单，可查看当日订单，不可修改/删除历史订单 |
| 订单明细表 | 读写（当日） | 随订单创建自动生成，不可单独修改 |
| 会员表 | 读 + 注册 | 可查看会员信息（不含敏感字段），可注册新会员，不可修改会员信息 |
| 员工表 | 无权限 | 不可查看任何员工信息 |

#### 不可操作/受限项
- ❌ 不可修改商品价格、分类等基本信息
- ❌ 不可查看员工薪资、身份证号等敏感信息
- ❌ 不可删除或修改历史订单（仅当日订单可操作）
- ❌ 不可审批大额退款（需店长审批）
- ❌ 不可创建或修改员工账号
- ❌ 不可查看财务报表和利润数据

---

### 3. 会员

#### 基本信息
- **角色定位**：注册会员顾客，享受积分和等级权益
- **使用系统方式**：前台/小程序端（自助查询），或通过店员操作

#### 核心职责

| 职责类别 | 具体职责 | 操作频率 |
|---|---|---|
| 购物消费 | 在小卖部购买商品，享受会员积分 | 按需 |
| 积分管理 | 查看个人积分余额、积分获取记录、积分消费记录 | 按需 |
| 消费记录 | 查看个人历史消费订单和消费明细 | 按需 |
| 个人信息 | 修改个人联系方式（手机号等） | 按需 |
| 会员权益 | 享受会员专属折扣、积分兑换礼品等权益 | 按需 |

#### 可操作数据范围

| 数据表 | 权限 | 说明 |
|---|---|---|
| 商品表 | 只读 | 可查看商品名称、单价、分类（前台展示） |
| 订单表 | 只读（本人） | 仅可查看与自己会员编号关联的订单 |
| 订单明细表 | 只读（本人） | 仅可查看本人订单的明细 |
| 会员表 | 读写（本人） | 可查看和修改本人的非敏感信息（手机号等），不可修改积分和等级 |

#### 不可操作/受限项
- ❌ 不可查看他人的订单和消费记录
- ❌ 不可修改商品信息和库存
- ❌ 不可操作任何员工相关数据
- ❌ 不可手动修改自己的积分余额（积分由系统自动累计）
- ❌ 不可提升自己的会员等级（等级由系统按消费自动升级）
- ❌ 不可查看其他会员的信息

---

### 4. 顾客（非会员）

#### 基本信息
- **角色定位**：普通散客，未注册会员
- **使用系统方式**：无需登录，直接到店消费

#### 核心职责

| 职责类别 | 具体职责 | 操作频率 |
|---|---|---|
| 购物消费 | 在小卖部购买商品，直接付款结账 | 按需 |

#### 可操作数据范围

| 数据表 | 权限 | 说明 |
|---|---|---|
| 商品表 | 只读 | 可查看商品价格（通过货架标签） |
| 订单表 | 无直接权限 | 订单由店员创建，非会员订单不关联个人信息 |

#### 不可操作/受限项
- ❌ 无系统账号，不登录系统
- ❌ 不存储个人信息，订单不关联会员编号
- ❌ 不享受积分和会员权益
- ❌ 不可查询历史消费记录（无身份标识）

## 四、后续权限设计要点

1. **基于角色的访问控制（RBAC）**：系统应采用RBAC模型，将权限绑定到角色而非个人，员工调岗时只需切换角色
2. **数据行级权限**：会员只能查看本人订单，需要在数据库层面实现行级安全策略
3. **敏感字段加密**：员工薪资、身份证号、会员手机号等敏感字段应加密存储，仅授权角色可解密查看
4. **操作审计日志**：所有关键操作（删除订单、修改价格、调整库存）应记录操作人、时间、内容，便于追溯
5. **密码安全存储**：员工登录密码严禁明文存储，应使用加盐哈希（如bcrypt）存储
