## 三、执行步骤

### 方法一：sqlcmd 命令行

```bash
# 1. 依次执行SQL脚本（替换为你的服务器、用户名和密码）
sqlcmd -S localhost -U sa -P your_password -i 01_create_database.sql
sqlcmd -S localhost -U sa -P your_password -d retail_store -i 02_create_tables.sql
sqlcmd -S localhost -U sa -P your_password -d retail_store -i 03_insert_sample_data.sql
sqlcmd -S localhost -U sa -P your_password -d retail_store -i 04_crud_operations.sql
```

或者先登录 sqlcmd 再逐个执行：

```bash
# 登录 SQL Server
sqlcmd -S localhost -U sa -P your_password

# 在 sqlcmd 中执行
:r C:/path/to/week3/01_create_database.sql
:r C:/path/to/week3/02_create_tables.sql
```

1. 打开 SSMS，连接到 SQL Server 实例
2. 点击"新建查询"
3. 依次打开每个 SQL 文件，点击"执行"按钮（或按 F5）
4. 执行顺序：01 → 02 → 03 → 04
5. 执行完成后在左侧对象资源管理器刷新，即可看到 retail_store 数据库及所有表

### 方法三：Navicat / DBeaver 等图形化客户端

1. 打开客户端，连接到 SQL Server

## 四、验证结果

执行完成后，可以通过以下 SQL 验证数据库是否正确创建：

```sql
-- 1. 查看数据库
SELECT name AS 数据库名, collation_name AS 排序规则, state_desc AS 状态
FROM sys.databases
WHERE name = 'retail_store';

-- 2. 选择数据库
USE retail_store;

-- 3. 查看所有表
SELECT name AS 表名, create_date AS 创建时间
FROM sys.tables
ORDER BY name;

-- 预期输出：
-- employee
-- inventory
-- member
-- order_item
-- orders
-- product

-- 4. 查看各表数据量
SELECT 'product' AS 表名, COUNT(*) AS 记录数 FROM product
UNION ALL SELECT 'member', COUNT(*) FROM member
UNION ALL SELECT 'employee', COUNT(*) FROM employee
UNION ALL SELECT 'inventory', COUNT(*) FROM inventory
UNION ALL SELECT 'orders', COUNT(*) FROM orders
UNION ALL SELECT 'order_item', COUNT(*) FROM order_item;

-- 预期输出：
-- product    10
-- member     5
-- employee   3
-- inventory  10
-- orders     10
-- order_item 20

-- 5. 查看表结构（以商品表为例）
SELECT COLUMN_NAME AS 字段名, DATA_TYPE AS 数据类型, IS_NULLABLE AS 允许空, COLUMN_DEFAULT AS 默认值
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'product'
ORDER BY ORDINAL_POSITION;

-- 6. 查看外键约束
SELECT
    fk.name AS 外键名,
    OBJECT_NAME(fk.parent_object_id) AS 子表,
    COL_NAME(fkc.parent_object_id, fkc.parent_column_id) AS 外键列,
    OBJECT_NAME(fk.referenced_object_id) AS 父表,
    COL_NAME(fkc.referenced_object_id, fkc.referenced_column_id) AS 引用列
FROM sys.foreign_keys fk
JOIN sys.foreign_key_columns fkc ON fk.object_id = fkc.constraint_object_id
ORDER BY 子表, 外键名;
```

## 五、建表与删除顺序

### 建表顺序（先被引用，后引用）

```
product → member → employee → inventory → orders → order_item
```

原因：
- `inventory` 引用 `product` 和 `employee`，所以这两张表必须先创建
- `orders` 引用 `member` 和 `employee`，所以这两张表必须先创建
- `order_item` 引用 `orders` 和 `product`，所以这两张表必须先创建

### 删除表顺序（与建表相反）

```
order_item → orders → inventory → employee → member → product
```

原因：
- 有外键引用的表不能先删除，否则会报错
- 必须先删除引用表，再删除被引用表

如果需要强制删除所有表（忽略外键约束）：

```sql
-- 先禁用所有外键约束
ALTER TABLE order_item NOCHECK CONSTRAINT ALL;
ALTER TABLE orders NOCHECK CONSTRAINT ALL;
ALTER TABLE inventory NOCHECK CONSTRAINT ALL;

-- 删除所有表
DROP TABLE IF EXISTS order_item;
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS inventory;
DROP TABLE IF EXISTS employee;
DROP TABLE IF EXISTS member;
DROP TABLE IF EXISTS product;
```

## 六、常见问题

### Q1：执行建表脚本时报外键约束错误

**原因**：外键引用的表或字段不存在，或者数据类型不匹配。

**解决**：
1. 确认建表顺序正确，被引用的表已经创建
2. 确认外键字段和引用字段的数据类型、长度完全一致
3. 确认引用字段是主码或有唯一索引

### Q2：插入数据时报 "Violation of PRIMARY KEY" 或 "Violation of UNIQUE KEY"

**原因**：插入了重复的主码或唯一键值。

**解决**：
1. 检查主码字段（如 product_id、member_id、order_id）是否重复
2. 检查唯一键字段（如 member.phone、employee.login_account）是否重复
3. 如果是重新执行脚本，先删除已有数据或先执行 02 脚本重建表

### Q3：插入数据时报 "The INSERT statement conflicted with the FOREIGN KEY constraint"

**原因**：插入的外键值在引用表中不存在。

**解决**：
1. 确认插入顺序正确，先插入被引用表的数据，再插入引用表的数据
2. 检查外键字段的值是否在引用表中存在
3. 例如：插入 inventory 前，确认 product_id 在 product 表中存在，last_updated_by 在 employee 表中存在

### Q4：IDENTITY 列插入指定值时报错

**原因**：默认情况下 IDENTITY 列不允许显式插入值。

**解决**：
1. 插入前执行 `SET IDENTITY_INSERT 表名 ON;`
2. 插入完成后执行 `SET IDENTITY_INSERT 表名 OFF;`
3. 本项目的 03 脚本已正确处理 IDENTITY_INSERT

### Q5：中文显示乱码

**原因**：数据库排序规则或客户端编码不支持中文。

**解决**：
1. SQL Server 默认排序规则通常支持中文（Chinese_PRC_CI_AS）
2. 确认使用 NVARCHAR 或 VARCHAR 配合中文排序规则
3. 本项目使用 VARCHAR，在中文排序规则下正常存储中文

### Q6：如何重置数据库（从头开始）

```sql
-- 方法一：删除数据库后重新创建
DROP DATABASE IF EXISTS retail_store;
-- 然后重新执行 01、02、03 脚本

-- 方法二：清空所有表数据（保留表结构）
-- 按外键依赖反序删除
DELETE FROM order_item;
DELETE FROM orders;
DELETE FROM inventory;
DELETE FROM employee;
DELETE FROM member;
DELETE FROM product;
-- 然后重新执行 03 插入样例数据
```

## 七、CRUD脚本执行注意事项

`04_crud_operations.sql` 是演示脚本，执行时会修改和删除数据：

1. **会插入测试数据**：会插入 P0011 商品、ORD202609160001 订单等测试数据
2. **会修改数据**：会修改 P0011 商品价格、P0001 库存数量、ORD202609160001 订单支付方式
3. **会删除数据**：最后会删除测试数据，恢复到原始状态
4. **约束验证部分**：被注释掉的 INSERT 语句是故意会报错的，用于演示约束生效，不要取消注释

如果只想查看原始样例数据，不要执行 `04_crud_operations.sql`，或者执行后重新执行 `03_insert_sample_data.sql` 恢复数据。
