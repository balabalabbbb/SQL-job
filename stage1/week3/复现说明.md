## 三、执行步骤

### 方法一：MySQL命令行

```bash
# 1. 登录MySQL
mysql -u root -p

# 2. 依次执行SQL脚本（在MySQL命令行中）
source C:/path/to/week3/01_create_database.sql
source C:/path/to/week3/02_create_tables.sql
source C:/path/to/week3/03_insert_sample_data.sql
source C:/path/to/week3/04_crud_operations.sql
```

或者在系统命令行中直接执行：

```bash
# 方式一：逐个执行
mysql -u root -p < 01_create_database.sql
mysql -u root -p < 02_create_tables.sql
mysql -u root -p < 03_insert_sample_data.sql
mysql -u root -p < 04_crud_operations.sql

# 方式二：合并执行（按顺序）
mysql -u root -p -e "source 01_create_database.sql; source 02_create_tables.sql; source 03_insert_sample_data.sql;"
```

1. 打开Navicat，连接到MySQL服务器
2. 点击"查询" → "新建查询"
3. 依次打开每个SQL文件，点击"运行"按钮执行
4. 执行顺序：01 → 02 → 03 → 04
5. 执行完成后在左侧导航栏刷新，即可看到retail_store数据库及所有表

### 方法三：phpMyAdmin

1. 登录phpMyAdmin
2. 点击"导入"选项卡
3. 选择 `01_create_database.sql` 文件，点击"执行"

5. 再次点击"导入"，依次导入 `02_create_tables.sql`、`03_insert_sample_data.sql`、`04_crud_operations.sql`

## 五、建表与删除顺序

### 建表顺序（先被引用，后引用）

```
product → member → employee → inventory → orders → order_item
```

原因：
- `inventory` 引用 `product` 和 `employee`，所以这两张表必须先创建
- `orders` 引用 `member` 和 `employee`，所以这两张表必须先创建
- `order_item` 引用 `orders` 和 `product`，所以这两张表必须先创建

### 删除表顺序（与建表相反）

```
order_item → orders → inventory → employee → member → product
```

原因：
- 有外键引用的表不能先删除，否则会报错
- 必须先删除引用表，再删除被引用表

如果需要强制删除所有表（忽略外键约束）：

```sql
-- 临时关闭外键检查
SET FOREIGN_KEY_CHECKS = 0;

-- 删除所有表
DROP TABLE IF EXISTS order_item;
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS inventory;
DROP TABLE IF EXISTS employee;
DROP TABLE IF EXISTS member;
DROP TABLE IF EXISTS product;

-- 重新开启外键检查
SET FOREIGN_KEY_CHECKS = 1;
```

## 六、常见问题

### Q1：执行建表脚本时报错 "Cannot add foreign key constraint"

**原因**：外键引用的表或字段不存在，或者数据类型不匹配。

**解决**：
1. 确认建表顺序正确，被引用的表已经创建
2. 确认外键字段和引用字段的数据类型、长度完全一致
3. 确认引用字段是主码或有唯一索引

### Q2：插入数据时报错 "Duplicate entry"

**原因**：插入了重复的主码或唯一键值。

**解决**：
1. 检查主码字段（如product_id、member_id、order_id）是否重复
2. 检查唯一键字段（如member.phone、employee.login_account）是否重复
3. 如果是重新执行脚本，先删除已有数据或使用 `INSERT IGNORE`

### Q3：插入数据时报错 "Cannot add or update a child row: a foreign key constraint fails"

**原因**：插入的外键值在引用表中不存在。

**解决**：
1. 确认插入顺序正确，先插入被引用表的数据，再插入引用表的数据
2. 检查外键字段的值是否在引用表中存在
3. 例如：插入inventory前，确认product_id在product表中存在，last_updated_by在employee表中存在

### Q4：CHECK约束不生效

**原因**：MySQL 8.0.16之前的版本不支持CHECK约束，会解析但忽略。

**解决**：
1. 升级到MySQL 8.0.16及以上版本
2. 或者使用触发器（TRIGGER）来实现数据校验
3. 本脚本中的CHECK约束在MySQL 8.0.16+中正常生效

### Q5：中文显示乱码

**原因**：数据库或表的字符集不是utf8mb4。

**解决**：
1. 确认创建数据库时使用了 `DEFAULT CHARACTER SET utf8mb4`
2. 确认客户端连接字符集为utf8mb4：`SET NAMES utf8mb4;`
3. 本脚本已统一使用utf8mb4字符集

### Q6：如何重置数据库（从头开始）

```sql
-- 方法一：删除数据库后重新创建
DROP DATABASE IF EXISTS retail_store;
-- 然后重新执行 01、02、03 脚本

-- 方法二：清空所有表数据（保留表结构）
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE order_item;
TRUNCATE TABLE orders;
TRUNCATE TABLE inventory;
TRUNCATE TABLE employee;
TRUNCATE TABLE member;
TRUNCATE TABLE product;
SET FOREIGN_KEY_CHECKS = 1;
-- 然后重新执行 03 插入样例数据
```

## 七、CRUD脚本执行注意事项

`04_crud_operations.sql` 是演示脚本，执行时会修改和删除数据：

1. **会插入测试数据**：会插入P0011商品、ORD202609160001订单等测试数据
2. **会修改数据**：会修改P0011商品价格、P0001库存数量、ORD202609160001订单支付方式
3. **会删除数据**：最后会删除测试数据，恢复到原始状态

如果只想查看原始样例数据，不要执行 `04_crud_operations.sql`，或者执行后重新执行 `03_insert_sample_data.sql` 恢复数据。
