# 存储过程与函数的区别 - 小卖部管理系统

## 一、基本概念

**存储过程（Stored Procedure）** 是一组预先编译并存储在数据库中的、可重复调用的 T-SQL 语句集合，它把一组完整的业务操作（查询、修改、事务、校验等）封装成一个独立的数据库对象，通过 `EXECUTE` 调用。

**函数（Function）** 是一种接收参数、经过计算后返回结果的数据库对象，分为标量函数（返回单个值）和表值函数（返回一个结果集），它强调"输入 → 计算 → 返回"，可以像普通表达式或表一样直接在 SQL 语句中使用。

本项目中：
- 存储过程：`usp_sales_statistics`（销售统计）、`usp_adjust_inventory`（库存调整）
- 函数：`fn_restock_qty`、`fn_sales_summary`、`fn_discount_rate`、`fn_discount_amount`、`fn_category_discount_rate`

## 二、核心区别对比

| 对比维度 | 存储过程 | 函数 |
|----------|----------|------|
| **返回方式** | 可返回 0 个、1 个或多个结果集，也可通过 OUTPUT 参数返回多个值，甚至不返回值 | 必须且只能返回一个结果：标量函数返回单个值，表值函数返回一个表 |
| **调用方式** | 用 `EXEC` / `EXECUTE` 单独调用，不能嵌入普通 SQL 语句 | 标量函数可在 `SELECT`、`WHERE`、计算列中直接使用；表值函数可放在 `FROM` 后像表一样查询或 JOIN |
| **参数方向** | 支持输入参数、输出参数（OUTPUT）、输入输出参数 | 只支持输入参数，没有 OUTPUT 参数 |
| **能否修改数据** | 可以执行 INSERT/UPDATE/DELETE、DDL、事务，能改变数据库状态 | 标量函数和内联表值函数通常只读，不能在函数内修改数据库数据、不能执行 DML/DDL |
| **错误处理** | 可以使用 `TRY...CATCH`、`THROW`、`RAISERROR`，能主动抛出错误并控制事务回滚 | 函数内**禁止**使用 TRY...CATCH、THROW、RAISERROR，异常只能通过返回 NULL 等方式由调用方处理 |
| **事务控制** | 可以显式开启、提交、回滚事务（BEGIN/COMMIT/ROLLBACK TRANSACTION） | 不能在函数内管理事务 |
| **返回值类型约束** | 结果集结构灵活，列数、列类型由内部查询决定 | 标量函数在定义时明确返回数据类型；表值函数明确返回表结构 |
| **典型用途** | 封装一个完整业务流程、需要写库或多步操作、需要事务和主动报错的场景 | 可复用的计算逻辑、需要在查询中反复调用、返回可参与 SELECT/JOIN 的结果 |
| **嵌套与组合** | 过程内可调用其他过程和函数 | 函数内可调用其他函数，但不能调用存储过程 |

## 三、结合本项目的具体说明

### 3.1 为什么库存调整用存储过程

库存调整 `usp_adjust_inventory` 需要：
1. 校验商品、操作员、数量、原因等多个输入；
2. 在事务内更新 `inventory` 库存表并向 `inventory_adjustment` 审计表插入记录；
3. 用更新锁（UPDLOCK）防止并发超扣；
4. 校验失败时主动 THROW 错误号并回滚事务。

这些操作涉及**写库、多表、事务和主动报错**，函数无法完成，因此必须用存储过程。

### 3.2 为什么补货量、折扣用函数

- 补货量 `fn_restock_qty`、折扣率 `fn_discount_rate`、折扣金额 `fn_discount_amount` 都是**纯计算**：给定输入返回一个确定的标量值，且需要在订单、库存等多处反复调用，用标量函数最自然。
- 销售汇总 `fn_sales_summary` 需要返回一张可查询的表，并能直接 `SELECT ... FROM fn_sales_summary(...)` 或与其他表 JOIN，因此用内联表值函数。
- 由于函数不能主动抛错，商品不存在、非法折扣等情况统一返回 `NULL`，交由调用方（Service / 存储过程）判断处理。

### 3.3 同一业务中两者的配合

销售统计页面同时使用了两类对象，体现了它们的分工：

| 部分 | 使用对象 | 原因 |
|------|----------|------|
| 整体汇总（订单数/数量/金额）+ 商品明细 | 存储过程 usp_sales_statistics | 需要完整封装统计逻辑、校验日期并主动报错 |
| 含全部商品的销售汇总表 | 表值函数 fn_sales_summary | 需要在 SELECT 中直接调用并返回完整表结构 |
| 下单折扣率、折扣金额 | 标量函数 fn_discount_rate / fn_discount_amount | 纯计算、可在 SQL 与应用中复用 |
| 库存调整与审计 | 存储过程 usp_adjust_inventory | 写库、事务、并发锁、主动报错 |

## 四、如何选择

| 需求特征 | 选择 |
|----------|------|
| 需要修改数据、写多张表 | 存储过程 |
| 需要事务控制、并发锁 | 存储过程 |
| 需要主动抛出错误、TRY...CATCH | 存储过程 |
| 通过 OUTPUT 返回多个值或多个结果集 | 存储过程 |
| 只是根据输入计算一个值 | 标量函数 |
| 需要在 SELECT / WHERE / 计算列中复用 | 标量函数 |
| 需要返回一张可查询、可 JOIN 的表 | 表值函数 |
| 计算逻辑只读、无副作用 | 函数 |

**一句话总结：** 存储过程适合"做一件事"（封装完整业务流程，可写库、可事务、可主动报错）；函数适合"算一个结果"（只读计算，返回值或表，可直接嵌入 SQL 语句）。本项目按这一原则划分对象，业务规则下沉到数据库，页面层只负责调用。
