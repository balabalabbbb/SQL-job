# 第7-9周 阶段报告：Web 应用开发

## 一、设计思路

### 1.1 总体架构

采用经典的**四层架构**：页面层 → 业务层 → 数据访问层 → 数据库层。每一层职责清晰，依赖关系单向向下。

选择 Flask 作为 Web 框架：轻量级、学习成本低、与 SQL Server 通过 pyodbc 连接成熟稳定。

### 1.2 核心设计决策

**(1) 事务管理放在业务层**：订单创建涉及多表写入（订单主表、订单明细、库存扣减、积分更新），事务边界在 `order_service.create_order()` 中定义。

**(2) 参数化查询**：所有 DAL 方法均使用 pyodbc 参数化查询（`?` 占位符），防止 SQL 注入。

**(3) 统一异常体系**：8 类业务异常继承自 `AppError`，每类对应明确的 HTTP 状态码。

**(4) 密码加密**：员工密码使用 bcrypt 哈希存储，登录时 `bcrypt.checkpw()` 验证。

**(5) 基于 Session 的权限控制**：登录后存储用户角色，每个路由验证登录状态和角色权限。

## 二、实验过程

### 2.1 环境准备

1. SQL Server 2019 中创建 `retail_store` 数据库，执行建库脚本和迁移脚本
2. 安装 Flask 3.1.3、pyodbc 5.3.0、bcrypt
3. 配置数据库连接（ODBC Driver 17 for SQL Server）

### 2.2 分层开发

- **DAL层**：`db.py` 实现连接管理、参数化查询、事务上下文；各实体 DAL 封装 CRUD
- **Service层**：`auth_service.py` 认证授权；`order_service.py` 订单事务（6步原子操作）；`exceptions.py` 统一异常
- **Routes层**：4个蓝图（认证、商品、库存、订单），全局异常处理和请求日志
- **前端模板**：base.html 继承体系，登录/首页/商品/库存/订单/创建订单页面

### 2.3 遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 登录401 | bcrypt哈希不对应已知密码 | 重新生成哈希并更新数据库 |
| 登录后500 | url_for('main.index')端点不存在 | 改为url_for('index') |
| 创建订单500 | order_status='已完成'违反CHECK约束 | 改为'已支付' |

### 2.4 集成测试

10个测试场景全部通过：登录、查询、正常下单、库存不足拒绝、非法外码拒绝、未登录拒绝、会员登录、顾客越权拒绝。

## 三、实验总结

### 3.1 完成情况

完成了可运行的小卖部管理 Web 应用：四层架构、员工/会员登录、商品/库存/订单CRUD、订单事务、角色权限、统一异常、日志记录、完整Web页面。

### 3.2 收获

1. 分层架构提升了代码可维护性
2. 事务保证了多表写入的数据一致性
3. 参数化查询防止注入且避免类型问题
4. 统一异常体系兼顾用户体验和安全性

### 3.3 改进方向

增加搜索分页、订单退款功能、统计仪表盘、生产环境使用WSGI服务器。
