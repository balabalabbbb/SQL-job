# 小卖部管理系统 - 第二阶段 Web 应用开发阶段报告

## 一、设计思路

### 1.1 项目背景

本项目基于第一阶段已完成的 SQL Server 数据库设计（v1.0），使用 Spring Boot 框架构建四层架构的 Web 应用程序，将数据库设计应用到实际业务场景中，实现从用户登录、Web 界面操作到数据写入的完整流程。

### 1.2 技术选型

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| 页面层 | Spring MVC + Thymeleaf | 轻量级模板引擎，与 Spring Boot 无缝集成，支持服务端渲染和会话管理 |
| 业务层 | Spring Service + @Transactional | 声明式事务管理，确保订单创建等多步操作的原子性 |
| 数据访问层 | Spring Data JPA + mssql-jdbc | 自动参数化查询，防止 SQL 注入，简化 CRUD 操作 |
| 数据库层 | SQL Server 2025 | 课程要求，支持完整的关系型数据库特性 |
| 安全 | Spring Security + Session | 会话管理、角色权限控制 |
| 构建 | Maven 3.9 + JDK 17 | 工业标准构建工具 |

### 1.3 四层架构设计

```
┌─────────────────────────────────────────┐
│  页面层 (Controller + Thymeleaf)         │
│  接收请求、参数校验、返回视图/JSON        │
├─────────────────────────────────────────┤
│  业务层 (Service)                        │
│  业务规则判断、事务边界、权限检查         │
├─────────────────────────────────────────┤
│  数据访问层 (Repository)                 │
│  参数化SQL、连接管理、事务提交/回滚       │
├─────────────────────────────────────────┤
│  数据库层 (SQL Server)                   │
│  表、约束、视图、数据、受限账户           │
└─────────────────────────────────────────┘
```

### 1.4 调用链路示例

**查询商品列表：**
```
浏览器 → ProductController.listProducts()
       → AuthService.requireLogin() [登录检查]
       → ProductService.getAllProducts()
       → ProductRepository.findAllWithCategory() [JPQL: LEFT JOIN FETCH]
       → SQL Server (SELECT + JOIN category)
```

**创建订单（事务）：**
```
浏览器 → OrderController.createOrder()
       → AuthService.canCreateOrder() [权限检查]
       → OrderService.createOrder() [@Transactional]
         1. ProductRepository.findById()     校验商品存在
         2. InventoryRepository.findByProductProductId() 校验库存
         3. 生成订单号 ORD+YYYYMMDD+4位序号
         4. OrderRepository.save()           写订单主表
         5. OrderItemRepository.save()       写订单明细
         6. InventoryRepository.deductStock() 扣减库存
         7. MemberRepository.addPoints()     更新会员积分
       → 任意失败 → 全部回滚
```

### 2.3 核心功能实现

#### 2.3.1 登录认证
- 员工登录：账号 + BCrypt 密码验证
- 会员登录：手机号直接登录
- Session 存储用户信息（userId, userName, userRole, userType）
- 未登录自动跳转登录页

#### 2.3.2 商品管理
- 列表查询（含类别名称，LEFT JOIN FETCH）
- 新增/修改/删除（仅店长权限）
- 后端校验：ID 非空、名称非空、价格非负、ID 重复检查
- 前端按角色隐藏操作按钮

#### 2.3.3 库存管理
- 列表查询（含商品名称）
- 低库存预警（数量 ≤ 阈值高亮）
- 库存数量调整（店员/店长权限）

#### 2.3.4 订单管理
- 列表查询（含会员、收银员信息）
- 订单明细查询
- 创建订单（7 步事务，原子性保证）
- 取消订单（事务：改状态 + 恢复库存 + 扣减积分）

### 2.4 安全机制

#### 2.4.1 三层权限控制
| 层级 | 控制方式 | 说明 |
|------|----------|------|
| 页面层 | Thymeleaf + JS 按角色隐藏按钮 | 店员/顾客看不到商品管理按钮 |
| 业务层 | AuthService.requireRole() | 越权操作抛 403 PermissionDeniedException |
| 数据库层 | retail_app 受限账户 | 仅有 DML 权限，无法 DROP/ALTER |

#### 2.4.2 统一异常处理
- 8 类自定义异常：Validation/Auth/PermissionDenied/NotFound/BusinessRule/Constraint/Database/Transaction
- GlobalExceptionHandler 统一拦截，返回标准 JSON 格式
- 前端只显示友好提示，不暴露 SQL/堆栈/连接信息
- 详细错误写入 `logs/app.log`，含时间、请求、错误码

#### 2.4.3 SQL 注入防护
- 所有查询通过 Spring Data JPA 自动参数化
- 无字符串拼接 SQL
- 输入在业务层进行类型、长度、范围校验

### 3.2 遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| Hibernate 懒加载序列化错误 | Jackson 无法序列化 HibernateProxy | @ManyToOne 添加 @JsonIgnore，外键列直接映射 |
| BCrypt 密码验证失败 | $2b$ 前缀 Spring Security 不兼容 | 生成 $2a$ 前缀 hash 更新数据库 |
| 中文 CHECK 约束冲突 | JDBC 连接未强制 Unicode | 添加 sendStringParametersAsUnicode=true |
| @Modifying 缺失 | UPDATE 查询被当作 SELECT | InventoryRepository.deductStock 添加 @Modifying |
| 员工登录浏览器失败 | 隐藏字段 required 导致表单验证拦截 | 动态设置 required，添加 name 属性 |
| 用户角色显示空白 | 模板 span 无填充代码 | Thymeleaf ${session.userRole} 服务端渲染 |

### 3.3 心得体会

1. **分层架构的价值**：通过 Controller→Service→Repository 的清晰分层，业务逻辑与数据访问分离，便于维护和测试。事务边界在 Service 层统一管理，确保数据一致性。

2. **事务的重要性**：订单创建涉及订单主表、明细、库存、积分多张表，任何一步失败都必须全部回滚。@Transactional 注解简化了事务管理，但需要正确配置 rollbackFor。

3. **安全不能只靠前端**：页面隐藏按钮只是用户体验，真正的权限控制必须在后端业务层和数据库层实现。本项目通过三层权限控制确保安全。

4. **统一异常处理**：8 类异常 + 全局处理器使得错误处理规范化，前端只需处理统一的 JSON 响应格式，后端日志保留详细信息便于排查。

5. **参数化查询**：使用 JPA 自动参数化从根本上防止 SQL 注入，比手动拼接字符串更安全可靠。
