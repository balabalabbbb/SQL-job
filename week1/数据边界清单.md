# 第一周 - 数据边界清单

## 一、数据边界划分原则

在确定哪些信息需要进入数据库存储时，遵循以下原则：

1. **交易核心原则**：直接参与交易流程、影响交易正确性的数据必须进库
2. **持久化原则**：需要长期保存、跨会话使用的数据必须进库
3. **可查询原则**：需要进行统计、分析、报表的数据必须进库
4. **关联原则**：与其他数据存在关联关系的数据必须进库
5. **最小化原则**：第一周只保留最小闭环所需数据，复杂功能后续扩展
6. **隐私保护原则**：涉及个人隐私的数据谨慎处理，敏感字段加密

## 二、进库数据清单

### 1. 商品相关数据

| 数据项 | 数据类型（参考） | 进库理由 | 所属核心对象 |
|---|---|---|---|
| 商品编号 | 字符串/整数 | 商品唯一标识，订单和库存都依赖此编号关联 | 商品 |
| 商品名称 | 字符串 | 交易核心信息，顾客和店员需要识别商品 | 商品 |
| 商品分类 | 字符串 | 便于商品管理和销售统计（如食品、饮料、日用品） | 商品 |
| 销售单价 | 十进制 | 订单计算总价的基础，必须持久化 | 商品 |
| 进货单价 | 十进制 | 店长核算利润需要，店员不可见但需存储 | 商品 |
| 计量单位 | 字符串 | 商品销售单位（瓶、包、个、斤等），影响数量计算 | 商品 |
| 供应商名称 | 字符串 | 补货时联系供应商，第一周先存名称，详情后续扩展 | 商品 |
| 生产日期 | 日期 | 食品类商品需要效期管理，临期商品需提醒 | 商品 |
| 保质期（天） | 整数 | 与生产日期配合计算到期日，过期商品不可销售 | 商品 |
| 商品状态 | 枚举 | 在售/下架/缺货，控制商品是否可被下单 | 商品 |

### 2. 库存相关数据

| 数据项 | 数据类型（参考） | 进库理由 | 所属核心对象 |
|---|---|---|---|
| 库存记录编号 | 整数 | 库存记录唯一标识 | 库存 |
| 商品编号 | 字符串/整数 | 与商品表关联，明确是哪个商品的库存 | 库存 |
| 当前库存数量 | 整数 | 交易核心，下单时自动扣减，补货时增加 | 库存 |
| 货架位置 | 字符串 | 店员找货和盘点需要，记录商品在货架的具体位置 | 库存 |
| 最低库存阈值 | 整数 | 库存预警的依据，低于此值触发补货提醒 | 库存 |
| 最后更新时间 | 日期时间 | 记录库存最后变动时间，便于追溯和盘点 | 库存 |
| 最后更新操作人 | 整数/字符串 | 记录谁最后修改了库存，操作审计需要 | 库存 |

|---|---|---|---|

## 三、不进库数据清单

### 1. 第一周明确不进库的数据

| 数据项 | 不进库理由 | 后续是否可能扩展 |
|---|---|---|
| 顾客实时聊天/咨询内容 | 小卖部为线下场景，无在线客服，口头交流无需记录 | 否 |
| 顾客面部识别/监控录像 | 涉及隐私，与交易核心无关，安防系统单独存储 | 否 |
| 商品图片 | 第一周最小闭环不需要，纯文字描述即可；后续可加图片URL字段 | 是（第2-3周可扩展） |
| 供应商详细联系方式 | 第一周补货流程简化，只存供应商名称；详细地址电话后续扩展 | 是（后续采购模块） |
| 促销活动/优惠券规则 | 复杂度较高，第一周只做原价交易；优惠计算后续阶段再加 | 是（第5-8周可扩展） |
| 员工薪资明细 | 敏感信息，第一周权限设计阶段不涉及薪资管理；后续可加密存储 | 是（后续人事模块） |
| 员工身份证号 | 敏感隐私信息，第一周最小闭环不需要；后续人事模块可加密存储 | 是（后续人事模块） |
| 采购订单/采购单明细 | 第一周补货为线下操作，不建采购单；后续可扩展采购管理模块 | 是（后续采购模块） |
| 盘点单/盘点明细 | 第一周库存调整简化处理，不单独建盘点单；后续可扩展 | 是（后续库存模块） |
| 交接班记录表 | 第一周交接班为线下操作，不建表；后续可扩展交接班记录 | 是（后续员工模块） |
| 操作审计日志 | 第一周简化处理，不单独建审计表；后续权限阶段可加 | 是（第4周授权阶段） |
| 会员收货地址 | 小卖部为线下到店消费，无配送需求，不需要地址 | 否（除非扩展线上外卖） |
| 顾客评价/评论 | 第一周无评价系统，后续可扩展 | 是（后续可选） |

### 2. 不进库但需注意的边界情况

| 数据项 | 处理方式 | 说明 |
|---|---|---|
| 非会员顾客的个人信息 | 完全不存储 | 非会员订单不记录姓名、电话等任何个人身份信息 |
| 购物小票 | 纸质凭证，不进库 | 系统中订单数据即为电子凭证，小票为打印件 |
| 现金找零金额 | 不单独存储 | 可通过支付金额-订单金额计算，第一周不记录实收现金 |
| 商品条形码 | 第一周不存储 | 假设店员手动选择商品，扫码功能后续可扩展加条码字段 |

## 四、数据边界总结

### 进库数据统计

| 核心对象 | 进库字段数（参考） | 说明 |
|---|---|---|
| 商品 | 10 | 商品基本信息+效期管理 |
| 库存 | 7 | 库存数量+位置+预警 |
| 订单 | 8 | 订单主表信息 |
| 订单明细 | 6 | 一单多商品的明细 |
| 会员 | 10 | 会员信息+积分+等级 |
| 员工 | 10 | 员工信息+登录凭证 |
| **合计** | **51** | 第一周最小闭环所需字段 |

### 不进库数据统计

| 类别 | 不进库项数 | 主要原因 |
|---|---|---|
| 隐私相关 | 3 | 监控录像、身份证号、薪资明细 |
| 后续扩展 | 8 | 促销、采购、盘点、审计等模块 |
| 场景不需要 | 3 | 聊天内容、收货地址、顾客评价 |
| **合计** | **14** | 第一周明确不进库的数据项 |

### 核心原则验证

- ✅ **商品**：进库，包含编号、名称、分类、单价等
- ✅ **库存**：进库，包含数量、位置、阈值等
- ✅ **订单**：进库，包含编号、时间、金额、支付方式等
- ✅ **订单明细**：进库，包含商品、数量、单价、小计等
- ✅ **会员**：进库，包含姓名、电话、积分、等级等
- ✅ **员工**：进库，包含姓名、岗位、账号、密码等

六类核心对象全部覆盖，数据边界划分符合最小闭环原则。
