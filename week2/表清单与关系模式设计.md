# 第二周 - 表清单与关系模式设计

## 一、实体与表总览

基于第一周确定的小卖部经营场景和数据边界，本周将六类核心业务对象转化为六张关系表。

| 序号 | 实体名称 | 表名 | 字段数 | 说明 |
|---|---|---|---|---|
| 1 | 商品 | `product` | 10 | 小卖部售卖商品的基本信息 |
| 2 | 库存 | `inventory` | 7 | 商品库存数量、位置和预警阈值 |
| 3 | 订单 | `orders` | 8 | 顾客交易订单的主表信息 |
| 4 | 订单明细 | `order_item` | 6 | 订单中每个商品的明细记录 |
| 5 | 会员 | `member` | 10 | 注册会员的个人信息和积分 |
| 6 | 员工 | `employee` | 9 | 店铺工作人员信息和登录凭证 |

## 二、表间关系图

```
┌──────────┐       ┌───────────┐       ┌──────────┐
│  member  │1─────N│  orders   │1─────N│order_item│
│  会员表   │       │  订单表    │       │ 订单明细表 │
└──────────┘       └─────┬─────┘       └────┬─────┘
                          │                    │
                          │N                   │N
                          │                    │
                     ┌────┴─────┐         ┌───┴────┐
                     │ employee │1        │ product│1
                     │  员工表   │         │ 商品表  │
                     └────┬─────┘         └───┬────┘
                          │1                    │1
                          │                     │
                     ┌────┴─────┐         ┌───┴────┐
                     │ inventory │1        │        │
                     │  库存表    │────────┘        │
                     └──────────┘                  │
                                                     │
                            ┌────────────────────────┘
                            │ 1
                     ┌──────┴───────┐
                     │  order_item  │
                     │   (product_id)│
                     └───────────────┘
```

**关系说明：**
- `member` 1:N `orders`：一个会员可以有多个订单，一个订单属于零个或一个会员（非会员订单member_id为空）
- `orders` 1:N `order_item`：一个订单包含多个订单明细，一个明细属于一个订单
- `product` 1:N `order_item`：一个商品可以出现在多个订单明细中，一个明细对应一个商品
- `employee` 1:N `orders`：一个员工（收银员）可以处理多个订单，一个订单由一个收银员处理
- `product` 1:1 `inventory`：一个商品对应一条库存记录
- `employee` 1:N `inventory`：一个员工可以更新多条库存记录，一条库存记录最后由一个员工更新

## 三、各表详细设计

### 3.1 商品表 `product`

**表说明**：记录小卖部所有售卖商品的基本信息，包括名称、分类、价格、供应商、效期等。

| 字段名 | 类型 | 长度/精度 | 允许空 | 默认值 | 域（取值范围/枚举） | 字段含义 | 码标注 |
|---|---|---|---|---|---|---|---|
| `product_id` | VARCHAR | 10 | 否 | — | 以'P'开头+4位数字，如P0001 | 商品唯一编号 | **PK（主码）** |
| `product_name` | VARCHAR | 100 | 否 | — | 非空字符串，不超过100字符 | 商品名称 | |
| `category` | VARCHAR | 20 | 否 | — | 枚举：'食品'/'饮料'/'日用品'/'文具'/'其他' | 商品分类 | |
| `sale_price` | DECIMAL | (8,2) | 否 | — | 大于0，最大999999.99 | 销售单价（元） | |
| `purchase_price` | DECIMAL | (8,2) | 否 | — | 大于0，小于等于sale_price | 进货单价（元） | |
| `unit` | VARCHAR | 10 | 否 | — | 枚举：'瓶'/'包'/'个'/'袋'/'盒'/'斤'/'其他' | 计量单位 | |
| `supplier` | VARCHAR | 50 | 是 | NULL | 字符串，供应商名称 | 供应商名称 | |
| `production_date` | DATE | — | 是 | NULL | 合法日期，不晚于当前日期 | 生产日期 | |
| `shelf_life_days` | INT | — | 是 | NULL | 大于0的整数 | 保质期（天） | |
| `status` | VARCHAR | 10 | 否 | '在售' | 枚举：'在售'/'下架'/'缺货' | 商品状态 | |

**候选码（UNIQUE候选）**：
- `(product_name, category, unit)`：商品名称+分类+单位的组合理论上可唯一标识，但考虑到可能有同名不同规格商品，不作为强制UNIQUE约束，仅作为候选码参考。

**外码（FK）**：无

**样例元组：**

### 3.2 库存表 `inventory`

**表说明**：记录每个商品的当前库存数量、货架位置、最低库存阈值，以及库存最后更新信息。

| 字段名 | 类型 | 长度/精度 | 允许空 | 默认值 | 域（取值范围/枚举） | 字段含义 | 码标注 |
|---|---|---|---|---|---|---|---|
| `inventory_id` | INT | — | 否 | 自增 | 大于0的整数，自增主键 | 库存记录唯一编号 | **PK（主码）** |
| `product_id` | VARCHAR | 10 | 否 | — | 必须存在于product表的product_id | 关联的商品编号 | **FK → product(product_id)**，UNIQUE |
| `quantity` | INT | — | 否 | 0 | 大于等于0的整数 | 当前库存数量 | |
| `shelf_location` | VARCHAR | 20 | 是 | NULL | 如'A-01'表示A区第1层货架 | 货架位置 | |
| `min_threshold` | INT | — | 否 | 10 | 大于等于0的整数 | 最低库存阈值（低于此值触发预警） | |
| `last_updated` | DATETIME | — | 否 | CURRENT_TIMESTAMP | 合法日期时间，不晚于当前时间 | 库存最后更新时间 | |
| `last_updated_by` | INT | — | 否 | — | 必须存在于employee表的employee_id | 最后更新操作人（员工编号） | **FK → employee(employee_id)** |

**候选码（UNIQUE候选）**：
- `product_id`：一个商品只能对应一条库存记录，因此product_id在本表中唯一，可作为候选码。

**外码（FK）**：
- `product_id` → `product(product_id)`
- `last_updated_by` → `employee(employee_id)`

**样例元组：**

| `order_time` | DATETIME | — | 否 | CURRENT_TIMESTAMP | 合法日期时间，不晚于当前时间 | 下单时间 | |
| `total_amount` | DECIMAL | (10,2) | 否 | 0.00 | 大于等于0，最大99999999.99 | 订单总金额（元） | |
| `payment_method` | VARCHAR | 10 | 否 | — | 枚举：'现金'/'微信'/'支付宝'/'其他' | 支付方式 | |

- `cashier_id` → `employee(employee_id)`

**表说明**：记录每个订单中包含的商品明细，一单多商品必须拆分明细，用于统计单品销量和计算订单金额。

| 字段名 | 类型 | 长度/精度 | 允许空 | 默认值 | 域（取值范围/枚举） | 字段含义 | 码标注 |
|---|---|---|---|---|---|---|---|
| `item_id` | INT | — | 否 | 自增 | 大于0的整数，自增主键 | 明细唯一编号 | **PK（主码）** |
| `order_id` | VARCHAR | 14 | 否 | — | 必须存在于orders表的order_id | 所属订单编号 | **FK → orders(order_id)** |

| `unit_price` | DECIMAL | (8,2) | 否 | — | 大于0，记录成交时的商品单价 | 成交时商品单价（元） | |

## 五、设计说明与注意事项

### 5.1 命名规范

- **表名**：全部小写，使用下划线分隔（如order_item），避免使用SQL保留字（订单表用orders而非order）
- **字段名**：全部小写，使用下划线分隔（如product_id、sale_price）
- **主码字段**：业务编码表使用"表名_id"格式（如product_id、member_id），自增表使用"表名_id"格式（如inventory_id、item_id）
- **外码字段**：与引用表的主码字段同名（如product_id引用product.product_id）

### 5.2 数据类型选择

- **编号类**：业务编码使用VARCHAR（如P0001、M0001、ORD202609150001），自增ID使用INT
- **金额类**：使用DECIMAL而非FLOAT/DOUBLE，避免浮点精度问题
- **时间类**：日期用DATE，日期时间用DATETIME
- **枚举类**：使用VARCHAR存储中文枚举值，配合CHECK约束限制取值范围
- **密码类**：使用VARCHAR(64)存储哈希值，严禁明文存储

### 5.3 完整性约束设计

- **实体完整性**：每张表都有主码，主码字段不允许为空
- **参照完整性**：所有外码引用的主码必须存在，外码可空的情况（如orders.member_id）表示可选关联
- **域完整性**：通过字段类型、长度、NOT NULL、DEFAULT、CHECK约束限制取值范围
- **用户定义完整性**：如purchase_price <= sale_price、subtotal = quantity × unit_price等业务规则

### 5.4 范式说明

本设计满足**第三范式（3NF）**：
- 所有字段都依赖于主码（1NF）
- 所有非主码字段都完全依赖于主码，不存在部分依赖（2NF）
- 不存在传递依赖，非主码字段不依赖于其他非主码字段（3NF）

例如：
- 订单明细中的unit_price（成交时单价）虽然可以从商品表获取，但为了记录历史成交价格（防止商品涨价影响历史订单），特意冗余存储在order_item表中，这是有意的反范式设计，不违反3NF的业务合理性。
