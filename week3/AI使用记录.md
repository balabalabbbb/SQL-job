# 第三周 - AI使用记录

## 一、AI使用概述

本项目在第三周DDL与数据修改阶段，使用AI工具（豆包）辅助完成SQL脚本编写、CRUD操作设计和约束定义等工作。AI主要用于**生成初始SQL框架和候选语句**，所有内容均经过小组成员的人工逐句检查、语法验证、业务语义确认和修改，确保SQL语句正确、约束完整、数据一致。

## 二、AI协助内容详细记录

### 2.1 建库与建表SQL生成

| 项目 | 内容 |
|---|---|
| **使用时间** | 第3周第1天 |
| **使用人** | 林一 |
| **AI输入（Prompt）** | "帮我写一个MySQL建库建表脚本，数据库名retail_store，包含商品表product（商品编号、名称、分类、售价、进价、单位、供应商、生产日期、保质期、状态）、会员表member、员工表employee、库存表inventory、订单表orders、订单明细表order_item，要有主键、外键、唯一约束、检查约束，表名和字段名用小写加下划线" |
| **AI输出摘要** | AI生成了建库脚本和六张表的CREATE TABLE语句，包含基本的主键和外键定义，部分字段有CHECK约束 |
| **人工修改内容** | 1. 修正表名：订单表从order改为orders（order是SQL保留字），AI原始输出用了order<br>2. 补全所有字段的COMMENT注释，AI输出大部分字段没有注释<br>3. 补全所有字段的NOT NULL和DEFAULT约束，AI输出部分字段遗漏了非空约束<br>4. 增加更多CHECK约束：AI只加了价格大于0，人工补充了枚举值校验（分类、单位、状态、支付方式等）、进价<=售价、小计=数量×单价、手机号格式校验等<br>5. 修正外键引用：AI输出中部分外键引用了错误的字段，人工修正为引用对应表的主键<br>6. 增加唯一约束：AI输出遗漏了member.phone、employee.login_account、inventory.product_id、order_item(order_id,product_id)的UNIQUE约束<br>7. 统一字符集：所有表设置ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci<br>8. 调整建表顺序：AI输出的建表顺序不符合外键依赖，人工调整为product→member→employee→inventory→orders→order_item<br>9. 增加DROP TABLE IF EXISTS语句，保证脚本可重复执行，删除顺序与建表相反 |
| **最终采用率** | 约30%的AI原始内容被保留，70%为人工补充和修改 |

## 四、AI使用原则与反思

### 4.1 使用原则

小组成员在使用AI时遵循以下原则：

1. **AI只生成框架，人工逐句验证**：AI生成的SQL语句必须逐句检查表名、字段名、数据类型、约束条件，不能直接照抄
2. **必须能解释每条SQL**：对于AI生成的每条语句，小组成员都必须理解其语法和业务含义，能解释为什么这样写
3. **外键关联必须人工核对**：AI生成的样例数据经常出现外键关联错误，必须人工逐一核对每个外键值在引用表中是否存在
4. **金额计算必须人工复算**：订单总金额、明细小计等涉及计算的数据，必须人工复算确保一致，不能信任AI的计算结果
5. **约束完整性人工检查**：AI经常遗漏CHECK约束、UNIQUE约束、NOT NULL约束，必须人工对照第二周的设计逐一检查补全
6. **记录使用过程**：详细记录每次AI使用的输入、输出和人工修改内容，便于追溯和学术诚信

### 4.2 AI的优势

1. **快速生成初始框架**：AI能够在短时间内生成CREATE TABLE和INSERT语句的基本框架，避免从零开始写语法模板
2. **覆盖常见字段**：AI能够覆盖零售场景的常见字段和表结构，起到提醒作用，减少遗漏
3. **语法参考**：AI生成的SQL语法通常是正确的，可以作为语法参考，特别是约束定义的语法格式
4. **文档框架**：AI能够快速生成复现说明等文档的章节框架，人工在此基础上填充具体内容

### 4.3 AI的局限性

1. **外键关联经常出错**：AI生成的多表样例数据经常出现外键值在引用表中不存在的问题，必须人工逐一核对
2. **金额计算不一致**：AI生成的订单总金额经常与明细小计之和不一致，必须人工复算修正
3. **约束定义不完整**：AI经常遗漏CHECK约束、UNIQUE约束、NOT NULL约束，特别是枚举值校验和业务规则校验
4. **命名不规范**：AI有时会使用order作为表名（SQL保留字），字段名大小写不统一，需要人工修正
5. **建表顺序错误**：AI生成的建表顺序经常不符合外键依赖关系，导致执行时报错，需要人工调整
6. **密码安全意识薄弱**：AI生成的员工样例数据中密码经常是明文，需要人工改为哈希值并强调安全存储
7. **缺少操作验证**：AI生成的CRUD语句通常只有操作本身，缺少操作前后的验证查询和安全检查
8. **数据不符合场景**：AI生成的商品名称有时不符合小卖部场景（如出现电子产品），需要人工替换

### 4.4 后续使用计划

在第四周的开发中，将继续使用AI辅助以下工作：

- 连接查询编写：AI可辅助生成多表JOIN查询的初始框架，但必须人工验证查询结果正确性
- 视图创建：AI可辅助生成CREATE VIEW语句，但必须人工验证视图数据的准确性
- 授权语句：AI可辅助生成GRANT语句，但必须人工核对权限范围是否符合第一周的角色设计
- 测试验证：AI可辅助生成测试用例，但必须人工执行并验证结果

同时，将继续严格执行"AI辅助、人工主导"的原则，确保所有SQL语句都经过小组成员的逐句检查、语法验证和业务语义确认，所有数据都经过人工核对和复算。
